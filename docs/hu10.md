# HU_10: ver estado de sincronización

> Estado: **parcialmente implementada** en el código. El contador de registros sin sincronizar y el estado por registro se muestran; no se muestra la fecha y hora de la última sincronización exitosa. Esta ficha resume el código actual frente a los criterios del requisito original.

## Historia

Como productor, quiero conocer el estado de sincronización de mis datos, para saber si ya están respaldados en el sistema central.

## Criterios y estado actual

| Criterio del requisito | Estado |
| --- | --- |
| Ver la fecha y hora de la última sincronización exitosa. | Pendiente: no se registra ni presenta ese dato. |
| Ver cuántos registros están pendientes. | Implementado: la barra superior muestra el total cuando es mayor que cero. Cuenta movimientos y actividades cuyo estado no es SYNCED. |
| Identificar registros en ERROR y ver cuáles son. | Parcial: el detalle/historial muestra el estado de cada movimiento; las actividades muestran su estado en las listas. No hay una pantalla central para ver todos los errores. |
| El indicador debe depender del estado de los registros, no solo de tener internet. | Parcial: el contador consulta estados locales. Cuando el total es cero, no aparece una etiqueta explícita de “todo sincronizado”. |
| Actualizar el indicador sin reiniciar la app. | Implementado para el contador y estados observados desde Room mediante flujos. |

## Comportamiento presente

- Estados usados: PENDING, SYNCING, SYNCED y ERROR.
- Las actividades y movimientos se sincronizan por separado; las actividades se envían antes que los consumos asociados.
- La barra superior cuenta registros en estados distintos a SYNCED, incluyendo actividades y movimientos.
- El historial de movimientos y las listas de actividades permiten consultar estados individuales.
- Un fallo temporal conserva el registro y permite reintento.

## Brechas para cerrar la HU

1. Guardar y mostrar fecha/hora de la última sincronización exitosa.
2. Mostrar de forma clara cuándo todo está sincronizado, incluso si el contador es cero.
3. Ofrecer un acceso sencillo a los registros en ERROR y permitir identificar qué tipo de error tienen.
4. Completar una verificación manual de los estados durante desconexión, reintento y recuperación de red.
